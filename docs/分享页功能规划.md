## 1. 一句话定位

**粘贴抖音链接 → 生成一个「在微信里点开就能看」的作品页 → 转发给任何人。**

现有产品解决"我要拿到无水印原片"，分享页解决"我要把这条视频给别人看"。前者是工具，后者是**社交传播入口**——它是本项目从工具站长出增长循环的唯一现实路径。

## 2. 用户痛点（为什么这个功能成立）

| 现状 | 用户实际遭遇 |
|---|---|
| 抖音链接发微信 | 点开是抖音的落地页，要求"打开抖音App"，微信内看不了正片 |
| 复制口令分享 | 一长串乱码文案，接收方要复制→切App→粘贴，三步流失 |
| 自己下载后发原片 | 微信压缩画质、大文件发不出去、群里刷屏 |
| 发给不装抖音的人 | 长辈、同事、海外朋友——直接看不了 |

**分享页的价值主张：一个链接，微信里点开就播，不装App、不跳转、不压缩。**

## 3. 红线与前置判断（做之前必须定的三件事）

这三条决定了产品形态，建议在开工前拍板。文档给出推荐值，后续章节均按推荐值展开。

### 3.1 分享页是否可被搜索引擎收录？

| 选项 | 收益 | 代价 |
|---|---|---|
| A. 全部 noindex（**推荐**） | 合规风险可控，仅凭链接访问 | 放弃 UGC 长尾 SEO 流量 |
| B. 全部收录 | 每条分享页 = 一个长尾着陆页，流量想象空间极大 | 等于建了一个搬运他人内容的内容站，版权投诉与平台打击是必然，不是概率 |
| C. 仅作者本人认领后可收录 | 合规且保留部分 SEO | 需要抖音账号归属验证，工程量大，短期不做 |

**推荐 A**：`<meta name="robots" content="noindex,nofollow">`，`/s/` 路径在 `robots.txt` 里 Disallow。SEO 流量继续靠现有工具词首页（已有 hreflang + JSON-LD 基建），不靠他人内容。

### 3.2 服务器是否落地存储视频文件？

**推荐：默认不落地，坚持现有"浏览器直连 CDN、服务器不存内容"原则。**

- 分享页只存**元数据快照 + video_id**，播放地址每次渲染时用 `_play_api(vid)` 重新拼装。
- 好处：法律上仍是"链接与元数据的再呈现"，且带宽成本可控。
- 代价：原作品被作者删除后，分享页失效（展示"内容已被原作者删除"）。这是**可接受的产品行为**，且应在生成时就明确告知用户。
- "永久存档"作为付费高级能力时，必须附加：权属声明勾选 + 强制私密 + 单独的存储计费。**不建议 6 个月内做。**

### 3.3 分享页默认有效期

**推荐：匿名 7 天 / 登录用户 30 天 / 会员 365 天或永久。** 有效期既是付费点，也是版权风险的自动衰减机制——过期页面自动变成"链接已失效"，历史存量不会无限累积成风险敞口。

## 4. 用户旅程

### 4.1 创建侧（现有用户）

```
粘贴链接 → 解析成功（现有流程）
        → 结果卡片新增按钮「🔗 生成分享页」
        → 弹层：短链 + 二维码 + 一键复制文案 + 一键存海报图
        → 可选：改标题 / 设密码 / 设有效期（会员）
        → 「我的分享」可查看访问数据
```

**关键交互原则**：生成分享页 **不新增一次解析配额消耗**（解析时已扣过），但生成动作本身要登录才能保存到「我的分享」——这是把匿名流量转化为注册用户的核心钩子。

### 4.2 消费侧（微信里收到链接的人，**大部分是新用户**）

```
微信聊天/朋友圈点开 → /s/{sid}
  → 首屏：封面 + 标题 + 作者（头像/昵称/回链原抖音）+ 互动数据
  → 点播放：微信内直接播（playsinline，不跳转、不全屏劫持）
  → 点下载：微信内 → 引导"右上角 ··· → 在浏览器打开"；浏览器内 → 直接下载无水印原片
  → 底部 CTA：「我也要生成这样的分享页 →」 回到首页
```

消费侧页面是**获客落地页**，不是普通详情页。它的第一 KPI 不是播放率，是 **CTA 点击率**。

|---|---|

| 我的分享 | 列表 / 数据 / 删除 / 改可见性与有效期 |

| 微信 JS-SDK 分享卡片 | 精确控制卡片标题/描述/缩略图，点击率提升显著（需认证服务号 + 备案域名） |

## 7. 技术方案（落到本仓库）

### 7.1 数据模型（`server.py` 的 `_SCHEMA` 追加）

```sql
CREATE TABLE IF NOT EXISTS shares(
  id TEXT PRIMARY KEY,             -- 短码，如 "k3Fq9x"（6-8位，Base58，避免易混字符）
  item_id TEXT,                    -- 抖音作品 id，用于惰性重解析刷新
  kind TEXT,                       -- video | note
  vid TEXT,                        -- video_id，播放地址每次用 _play_api(vid) 重拼
  owner_user_id INTEGER,           -- 创建者，可空（匿名）
  owner_fp TEXT,                   -- 匿名创建者指纹/IP，用于追溯与限频
  title TEXT, author TEXT, avatar TEXT, cover TEXT,
  payload TEXT,                    -- 解析结果 JSON 快照（不含媒体字节）
  custom_title TEXT,               -- 用户自定义标题（会员）
  visibility TEXT DEFAULT 'link',  -- link | password | private
  pw_salt TEXT, pw_hash TEXT,
  expires_at INTEGER,              -- 0 = 永久
  refreshed_at INTEGER,            -- 上次刷新直链时间
  status TEXT DEFAULT 'ok',        -- ok | dead(源已删) | takedown(被投诉下架)
  views INTEGER DEFAULT 0, plays INTEGER DEFAULT 0,
  downloads INTEGER DEFAULT 0, cta_clicks INTEGER DEFAULT 0,
  created INTEGER
);
CREATE INDEX IF NOT EXISTS idx_shares_owner ON shares(owner_user_id);
CREATE INDEX IF NOT EXISTS idx_shares_item  ON shares(item_id);

CREATE TABLE IF NOT EXISTS share_events(
  id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER, sid TEXT,
  kind TEXT,                       -- view | play | download | cta | fallback
  ip TEXT, ua TEXT, referer TEXT, wechat INTEGER, fp TEXT
);
CREATE INDEX IF NOT EXISTS idx_share_ev ON share_events(ts, sid);
```

`shares` 落 SQLite（需要持久化 + 查询），**不要**放进 `data/config.json`（那是代理池专用）。所有访问走现有 `db_exec()` + `_db_lock`。

### 7.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/share` | 由 `text` 或 `item_id` 生成分享页；命中 `_cache` 则零解析成本 |
| GET | `/s/{sid}` | 服务端渲染 HTML（HTML 页面，不是 JSON） |
| GET | `/api/share/{sid}` | 分享页 JSON（前端刷新/校验用） |
| POST | `/api/share/{sid}/event` | 埋点上报（play/download/cta/fallback） |
| GET | `/s/{sid}/qr.svg` | 二维码 |
| GET | `/api/shares` | 我的分享列表（需登录） |
| DELETE | `/api/shares/{sid}` | 删除（本人或管理员） |
| POST | `/api/v1/shares` | 开放 API 版；若实现，必须复用 `job_items` + `api_ledger` 的预授权、租约与幂等结算 |
| POST | `/api/report` | 侵权投诉（公开，无需登录） |
| GET/POST | `/api/admin/shares` | 后台：搜索、下架、封创建者 |

代码位置：在 `server.py` 的「核心解析」与「公共 API」之间新增 `# ----- 分享页` 分区，保持现有单文件分层结构。

### 7.3 直链保鲜策略（决定分享页"能活多久"）

| 类型 | 保鲜方式 | 说明 |
|---|---|---|
| 视频 | 存 `vid`，每次渲染重拼 `_play_api(vid)` | 该地址不含签名与时效参数，**天然长期有效**，这是本方案成立的技术基础 |
| 封面/头像 | CDN 直链，一般较稳 | 加载失败时前端隐藏，不影响主体 |
| 图集图片 | CDN 直链**会过期** | 渲染时若 `now - refreshed_at > 24h` 或前端 `onerror` 上报 → 后台按 `item_id` 重走 `_parse_cached()` 刷新 `payload` |
| 源作品被删 | 刷新失败 → `status='dead'` | 展示"内容已被原作者删除"，保留标题与作者署名 |

刷新走 `open_url()`（即走代理池），要做**每 sid 每小时最多刷新 1 次**的限频，否则热门分享页会把代理池打爆。

### 7.4 与现有体系的衔接

- **出站请求**：任何新增的抖音请求必须经 `open_url()`，禁止直接 `urlopen`。刷新与兜底播放都受 `force_proxy` 保护。
- **配额**：生成分享页时若能命中 `_cache` 或已有 `shares` 记录 → 不扣配额；需要真实解析才扣 1 次。分享页**被访问**不扣创建者配额。
- **SSRF**：分享页里所有 CDN 地址仍受 `ALLOWED_HOST_SUFFIXES` 白名单约束。
- **SEO 模板**：分享页需要 **per-share 动态 OG**，不能复用现有的 `_seo_head()`。新增 `_share_head(share, origin)` 生成 `og:title`（作品标题+作者）、`og:image`（封面）、`robots: noindex`。
- **模板占位**：新增 `static/share.html`，同样用占位符 + 路由渲染（本项目没有 StaticFiles 挂载，直接放静态文件会导致占位符原样输出）。
- **多进程**：分享页本身无内存态，可安全多 worker；但登录态仍是内存字典，"我的分享"页面在多 worker 下会掉线——这是既有约束，不因本功能改变。

### 7.5 新增依赖

只建议加 `segno`（纯 Python、零依赖、输出 SVG 二维码）。海报合成走前端 canvas，不引入 PIL。保持 `requirements.txt` 的轻量。

## 8. 微信兼容专项（本功能成败的 90%）

> ⚠️ 以下均为基于微信内核已知行为的**设计假设**，未在本项目实测。开工第一天就应按 §10 的清单逐条验证，验证结果直接决定 P0 能否交付。

### 8.1 播放

```html
<video src="..." poster="封面"
       playsinline webkit-playsinline x5-playsinline
       x5-video-player-type="h5" x5-video-player-fullscreen="false"
       preload="metadata" controls></video>
```

- 不自动播放（微信限制自动播放，且移动流量场景下自动播是骚扰）。
- `x5-video-player-type="h5"` 阻止安卓 X5 内核劫持成全屏原生播放器。
- **播放源三级降级**：① 直连 `aweme.snssdk.com`（零服务器成本）→ ② `onerror`/8 秒无 `canplay` → 自动切 `/api/video/{vid}`（走代理，吃服务器带宽）→ ③ 仍失败 → 展示封面 + "在浏览器中打开"引导。每次降级都要 `fallback` 埋点，**这是带宽成本的核心监控指标**。

### 8.2 下载

微信内置浏览器禁止直接下载 mp4。**不要试图绕过**，正确做法是引导：点击下载 → 全屏蒙层 + 右上角箭头动画 + "点击 ··· 选择「在浏览器中打开」" + 一键复制链接按钮。这是微信生态的标准做法，用户认知成本低。

### 8.3 分享卡片

| 方案 | 效果 | 成本 |
|---|---|---|
| 裸页面（P0） | 微信抓 `<title>` + 页面首图，卡片较朴素 | 0 |
| JS-SDK（P1） | 精确控制标题/描述/封面缩略图，**卡片点击率通常有数倍差距** | 认证服务号 ¥300/年 + 域名 ICP 备案 + 签名接口 |

JS-SDK 需要 `jsapi_ticket`（7200s 有效、全局唯一、有调用频次上限）。本项目**必须把 ticket 存进 `app_settings` 表**而不是内存字典——否则多 worker 各自刷新会互相顶掉。

### 8.4 域名被封（最大的运营风险）

微信对"下载类/侵权类/诱导分享类"域名的拦截是**常态而非意外**。必须按"域名一定会被封"来设计：

1. **域名池**：主站域名与分享域名**物理隔离**。分享用 3–5 个独立域名（`SHARE_DOMAINS` 环境变量），生成时按权重轮换。主站被牵连 = 灾难；分享域名被封 = 日常。
2. **短码全局解析**：`sid` 与域名解耦，同一个 `sid` 在任意分享域名下都能打开。某域名被封 → 后台一键把该域名下的存量分享指向备用域名。
3. **被封检测**：定时用外部渠道探测各分享域名可用性 + 页面内埋点上报异常 + 用户反馈入口，三路兜底。
4. **文案自律**：页面与分享文案**不出现**"点击下载""转发得""破解""去水印"等触发词；微信内 UA 下对"下载"字样做弱化呈现（改为"保存原片"并折叠到二级）。
5. **流量资产化**：域名是**租来的**，公众号/小程序/邮件列表才是自己的。分享页应有一个低干扰的"防失联"引导，把用户沉淀到可持有的渠道。
6. **小程序方案要现实**：把分享做成微信小程序卡片确实最抗封，但**"抖音视频下载"类目小程序基本不可能过审**。除非彻底重新包装成不含下载功能的"素材管理/内容协作"工具。**列为高风险探索项，不进 P0/P1 主路径。**

### 8.5 备案

面向国内用户的分享域名需 ICP 备案，否则国内访问链路本身就不稳，且更易被微信拦截。这会连带决定服务器放境内还是境外——**是个需要提前 20–30 天启动的前置事项**，不要等功能做完才发现卡在这里。

## 9. 埋点与北极星指标

**北极星指标：每个分享页带来的新访客数（Visitors per Share, VPS）。**

```
VPS = 分享页 UV / 分享页创建数
K   = VPS × (CTA 点击率 × 新访客解析成功率)
```

K > 1 意味着自增长。现实中工具类产品 K 通常在 0.1–0.3，**目标是把获客成本压低，而不是幻想病毒式爆发**。

| 层级 | 指标 |
|---|---|
| 创建侧 | 解析→生成分享页转化率、人均生成数、匿名→注册转化率 |

## 10. P0 实测验证清单（开工第一天做，全部通过才继续）

| # | 验证项 | 不通过的后果 |
|---|---|---|
| 1 | 微信 iOS / 安卓内核下，`aweme.snssdk.com` 播放地址能否直连播放 | **致命**。若不能，全部播放走服务器兜底，带宽成本模型重写 |
| 2 | 微信内 `<video>` 是否被 X5 劫持全屏 | 影响体验，有已知参数可解 |
| 3 | 微信抓取裸页面生成的卡片长什么样 | 决定 JS-SDK 是否要提前到 P0 |
| 4 | 新域名首次在微信内传播是否被拦 | 决定备案与域名池的启动时点 |
| 5 | 图集 CDN 直链在微信内是否可见、可长按保存 | 决定图集分享页形态 |
| 6 | 分享页在 QQ / 飞书 / 钉钉 / Safari / 海外场景的表现 | 微信被封时的备用传播渠道 |

**建议先用一个廉价的独立域名跑 1 周灰度**，再决定是否把这个功能接到主域名的产品动线里。

## 12. 明确不做

- 不做视频转存/永久存档（除非付费 + 权属声明 + 强制私密）
- 不做分享页的搜索引擎收录（除非作者认领）
- 不做内容聚合/排行榜/推荐流——那是内容平台，风险量级完全不同
- 不做"诱导转发解锁"（微信明令禁止，且与"永不接广告"的品牌承诺冲突）
