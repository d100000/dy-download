# 机场订阅接入（mihomo）

有两种用法，二选一：

- **方式二：项目内置（后台一键，推荐）** —— 后台粘贴订阅链接即可，内核由本项目自动下载、管理、随项目启停。多数人用这个，见下方「方式二」。
- **方式一：独立部署（手动边车）** —— 自己在服务器上跑一个 mihomo，本项目代理池填它的本地端口。需要精细控制或已有 mihomo 时用，见下方「方式一」。

两者原理相同（mihomo 吃订阅、落地成本地统一端口），区别只是谁来管理这个 mihomo 进程。

---

本项目的代理池只支持 `http / https / socks5 / socks4`（`urllib` + `PySocks`）。机场订阅里是 **vmess / vless / trojan / shadowsocks / hysteria2 / tuic** 等加密协议，PySocks 不会解，**不能直接导进代理池**。

正确做法：让 **mihomo**（Clash.Meta 内核）吃订阅，在本地落地成一个统一端口，抖音下载器的代理池只填这一个本地地址。多节点轮换、测速、故障自动切换全部由 mihomo 完成。

```
机场订阅 ─→ mihomo(127.0.0.1:7890) ─→ 抖音下载器代理池只填 socks5://127.0.0.1:7890
             │
             └ 自动拉订阅 / 自动测速 / 自动切换故障节点（内核原生功能）
```

你要的三件事 mihomo 原生就有，本项目一行代码都不用改：

| 需求 | mihomo 功能 |
|---|---|
| 一键导入所有节点 | `proxy-providers` 填订阅 URL，自动拉全部节点 |
| 自动测可用性 | `health-check` 定时对每个节点测延迟 |
| 自动更换通道 | `url-test` 选最快 / `fallback` 挂了自动切下一个 |
| 定时刷新订阅 | `proxy-providers` 的 `interval` 自动重拉 |

# 方式二：项目内置（后台一键，推荐）

不用碰宝塔、不用自己下内核、不用写 systemd。整套 mihomo 生命周期由本项目托管。

## 用法

1. 进 `/admin_d` 管理后台 → 代理页 →「内置机场加速（mihomo）」面板。
2. 把机场订阅链接粘进去，点「保存并启动」。
3. 首次会自动下载 mihomo 内核（几十 MB，国内服务器慢的话耐心等，状态会从「下载中→启动中→运行中」）。
4. 起来后代理池里会自动出现一条 `内置机场加速（mihomo）` 的托管条目，无需手动填。停用时点「停用」，该条目自动移除。

订阅刷新、节点测速、故障切换全由 mihomo 内核自动完成，本项目只负责起停和把本地端口接进代理池。

## 只有本项目能用（隔离设计）

这是内置方式相对独立部署的关键优势——落地端口是**项目私有**的，同一台服务器上的其他程序连不进来：

- **只绑 `127.0.0.1`**（`bind-address: 127.0.0.1` + `allow-lan: false`）：外网和局域网都访问不到，只有本机进程能连。
- **随机高端口**（20000–60000，首次生成后持久化在 `app_settings`）：不占用 7890 之类的公共端口，不和别的 clash/v2ray 撞。
- **账号密码鉴权**（`authentication`，随机用户名 + 随机密码，`skip-auth-prefixes: []` 连本机也要验证）：就算别的进程猜到端口，没有本项目自己生成的凭据也连不上。凭据只存在 `app_settings` 里，由 `open_url()` 内部使用。
- **不设系统代理、不开 TUN**（`tun.enable: false`）：不改服务器的 `http_proxy` 环境变量、不接管全局流量，别的项目的出站完全不受影响。

## 绝不直连（fail-closed）

机场全部节点挂掉 / 订阅拉不到时，mihomo 的 `fallback` 组里挂了一个永远失败的 `blackhole` 成员兜底，使分组永不为空——因此**不会**回落到内核的 `DIRECT`（COMPATIBLE）而暴露服务器真实 IP，出站直接失败。这与本项目「没有可用代理宁可 503 也绝不直连」的底线一致。

## 相关环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `MIHOMO_VERSION` | `v1.18.10` | 内核版本 |
| `MIHOMO_DL_BASE` | GitHub releases | 内核下载源；服务器连不上 GitHub 时换镜像 |
| `MIHOMO_OFF` | 关 | 设 `1` 彻底禁用内置机场（即使配了订阅也不启动） |

## 注意事项

- 内核以**子进程**方式随本服务启动，服务停止时一并关闭；用 pidfile 清理孤儿进程，避免重启后残留。
- 端口/凭据首次生成后持久化，重启复用；若端口被别的程序占了，改 `app_settings` 里的 `mihomo_port` 或直接删掉让其重新随机。
- 默认单 worker 运行。多 worker 会有多个进程抢着起内核，务必保持单 worker（本项目本来就要求单 worker）。

# 方式一：独立部署（手动边车）

> 已有 mihomo、或想自己精细控制内核时用。否则优先用上面的「方式二」。

## 一、下载 mihomo 内核

在服务器上（宝塔终端）：

```bash
mkdir -p /www/mihomo && cd /www/mihomo

# 到 https://github.com/MetaCubeX/mihomo/releases 找最新版
# 选 linux-amd64（x86 服务器）或 linux-arm64（ARM 服务器）
wget https://github.com/MetaCubeX/mihomo/releases/download/v1.18.10/mihomo-linux-amd64-v1.18.10.gz
gunzip mihomo-linux-amd64-v1.18.10.gz
mv mihomo-linux-amd64-v1.18.10 mihomo
chmod +x mihomo
```

> 版本号会变，去 releases 页面取当前最新的下载链接即可。

## 二、写配置 `/www/mihomo/config.yaml`

把 `url` 换成你自己的机场订阅链接（截图里那条 `https://appv3.nloli.xyz/tako_api/secure?token=...`）：

```yaml
mixed-port: 7890            # 一个端口同时提供 http 和 socks5
allow-lan: false           # 只允许本机访问，安全
mode: rule
log-level: warning

# 机场订阅（自动拉取全部节点）
proxy-providers:
  jichang:
    type: http
    url: "https://appv3.nloli.xyz/tako_api/secure?token=你的完整token"
    path: ./providers/jichang.yaml
    interval: 3600           # 每小时自动刷新订阅
    health-check:
      enable: true
      url: https://www.gstatic.com/generate_204
      interval: 300          # 每 5 分钟测一次每个节点延迟

proxy-groups:
  - name: auto               # 自动选最快、故障自动切换
    type: url-test
    use: [jichang]
    url: https://www.gstatic.com/generate_204
    interval: 300
    tolerance: 50            # 延迟差 50ms 内不频繁切换，避免抖动

rules:
  - MATCH,auto               # 所有流量走 auto 组
```

关键点：

- `mixed-port: 7890` 让同一端口既是 http 代理又是 socks5 代理，抖音下载器填 `socks5://127.0.0.1:7890` 即可。
- 配置文件里含订阅 token，**设好权限**：`chmod 600 /www/mihomo/config.yaml`。
- 想在网页看节点状态可加 `external-controller: 127.0.0.1:9090` 再配面板，非必需。

## 三、宝塔里让 mihomo 常驻运行

mihomo 是 Go 二进制，不能用「Python 项目管理器」跑。用宝塔的 **Supervisor 管理器**（软件商店搜索安装）：

Supervisor 管理器 → 添加守护进程：

| 配置项 | 填写 |
|---|---|
| 名称 | mihomo |
| 运行目录 | `/www/mihomo` |
| 启动命令 | `/www/mihomo/mihomo -d /www/mihomo` |
| 进程数量 | 1 |
| 启动用户 | root |

保存后它会自动启动并守护（挂了自动拉起）。

**或者用 systemd**（不装 Supervisor 时）——建 `/etc/systemd/system/mihomo.service`：

```ini
[Unit]
Description=mihomo
After=network.target

[Service]
WorkingDirectory=/www/mihomo
ExecStart=/www/mihomo/mihomo -d /www/mihomo
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now mihomo
```

## 四、验证 mihomo 通了

```bash
# 通过本地代理访问，能返回一个境外 IP 就说明节点通了
curl -x socks5h://127.0.0.1:7890 https://api.ipify.org ; echo
# 测抖音可达性
curl -x socks5h://127.0.0.1:7890 -I https://www.douyin.com
```

看日志排错：`tail -f /www/mihomo/logs/*.log`，或宝塔 Supervisor 管理器里看该进程日志。

## 五、加进抖音下载器代理池

打开 `https://你的域名/admin_d` → 代理 → 添加代理，只填一条：

```
socks5://127.0.0.1:7890
```

点「测速」，看到出口 IP 是机场节点的境外 IP、抖音可达即成功。之后本项目所有解析请求都会走这一条 → mihomo → 自动挑最快的机场节点；某节点挂了 mihomo 自动切换，你的下载器无感。

> 小技巧：本项目代理池的「默认协议」保持 socks5 即可。填 `socks5h://127.0.0.1:7890` 也行（h = 远端 DNS 解析，避免本地 DNS 泄露），效果一样。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| curl 走代理超时 | 订阅没拉成功（token 过期/服务器连不上机场面板），看 mihomo 日志；或该机场全部节点当前不可用 |
| 抖音下载器测速失败但 curl 能通 | 检查填的是 `127.0.0.1` 不是 `0.0.0.0`；端口对不对 |
| 节点频繁切换 | 调大 `tolerance`；`interval` 别设太小 |
| 想换机场 | 改 `config.yaml` 里的 `url`，重启 mihomo 进程即可，抖音下载器那边不用动 |
| 订阅有流量限制 | 本项目只解析元数据（几十 KB/次），字节走用户浏览器直连，机场流量消耗极小 |

---

**总结**：机场节点接入 = 部署一个 mihomo 边车，抖音下载器代理池只填 `socks5://127.0.0.1:7890`。测速、切换、刷新订阅全交给 mihomo，本项目零改动。
