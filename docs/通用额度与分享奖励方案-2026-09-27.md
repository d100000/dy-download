# 通用额度与分享奖励

适用版本：v1.34.0。仅适用于根目录完整版的网页解析与分享功能。

## 两种次数与使用顺序

| 项目 | 来源 | 有效期 | 使用顺序 |
| --- | --- | --- | --- |
| 每日免费额度 | 全局配置或管理员对某用户单独配置 | 按现有每日计数周期更新，不累计 | 第一顺位 |
| 通用额度 | 分享奖励、管理员赠送、购买入账 | 长期有效，不每日清零 | 第二顺位 |
| 网页账户余额 | 既有余额充值 | 沿用现有规则 | 两种次数均用完后按价格扣费 |

“通用额度”用“次”计量，1 次对应成功解析一条作品。批量请求按成功条数结算。预占、成功结算、失败退款及进程重启后的回收均记录来源，不能重复扣费、发奖或退款。语音转文字和开放 API 密钥使用各自原有计费，不消耗本次新增的通用额度。

单用户每日设置为空时跟随全局；设置为 0 表示该用户没有每日赠送次数。调整立即影响新的请求，但不清空当天已用次数，也不改已经预占的任务。管理员可在“用户”中分别编辑每日额度和通用额度，后者展示可用、预留、累计消费及最近流水。

后台“购买入账”用于管理员确认已收款后增加次数并记录来源，不会发起支付或从用户余额扣款。未来接入支付渠道时应由经过验证且幂等的支付成功回调入账；此次没有增加支付网关或自动购买入口。

## 分享奖励规则

1. 分享者必须是有效登录账号，分享页必须可访问、未过期、未下架。
2. 访客从分享页进入生成入口，或进入携带该分享 `ref` 的首页，服务端建立 24 小时归因。归因本身不奖励。
3. 访客登录本站并成功完成一次网页解析、批量解析或新分享解析后，服务端在成功结算事务内给分享者增加 1 次通用额度。批量成功多条只产生一次奖励。复用已有快照直接生成分享而未发生额度结算时，不奖励。
4. 仅浏览、刷新、播放、下载、状态轮询、语音文案或开放 API 调用不奖励。失败任务不奖励；失败后可在归因有效期内正常重试。
5. 同一分享者的同一原作品，按平台、作品类型及作品 ID 合并计算，最多获赠 5 次；重建短链接、删除分享页或清理访问日志不能重置这个上限。
6. 同一账号对同一分享者只奖励一次。相同浏览器标识或网络范围也不重复奖励；更换账号、重放请求或并发提交不能增加奖励。

## 防重复与风险判断

分享防刷使用服务端签名的 HttpOnly 随机 Cookie，与账号和网络摘要共同校验；不依赖前端可随意填入的 `X-FP`，不采集硬件指纹。IPv4 按 `/24`、IPv6 按 `/64` 归并网络，IPv4 映射 IPv6 先统一格式。

归因 Cookie 不能自行构造，且与访问时的浏览器、网络和首次登录账号绑定。预占时验证一次，成功结算时再验证账号、分享状态、作品身份、重复记录及上限。奖励记录、账户次数和额度流水与成功任务在同一 SQLite 写事务中提交；任何记账错误都整体回滚。已发奖的成功任务后续被管理员退款不会重复奖励，也不会强制扣回分享者可能已用完的额度，保留账本用于审计。

账户登录和创建分享时记录近期浏览器/网络摘要，拦截自己分享给自己、同一浏览器换号、同一网络多账号等情况。访问归因每浏览器每小时最多 20 条、每网络每小时最多 60 条、全站每小时最多 10000 条；重复打开可复用有效归因。超限不影响正常页面和解析，仅跳过奖励归因。

这些是基础风控，无法证明两个账号一定属于两个独立真人。本站当前未验证邮箱所有权，也没有实名或手机验证；控制多个账号、设备与代理出口仍可能绕过部分判断。同一家庭、公司或运营商网段内的正常用户也可能不获奖励。页面需明确“符合条件才发放”，不承诺每次分享必得额度。

## 数据与升级

- `users` 新增单用户每日限额、设置版本，以及通用额度的可用/预留/消费/版本字段。旧用户默认跟随全局，通用额度初始为 0。
- `quota_reservations` 记录预占的通用额度和分享归因，确保失败/重启按原来源退回。
- `credit_ledger` 记录赠送、购买、分享奖励、预占、结算和退款，管理员提交使用请求 ID 与版本校验。
- `referral_visits` 保存短期归因，24 小时过期后清理。`referral_identity_signals` 限制每账号每类最近 128 项。
- `share_credit_rewards` 与额度流水长期保留必要的账号、作品及用途隔离摘要，保证上限和去重不随访问日志清理而失效；不保存原始 IP、Cookie 或硬件指纹。已同步中英文隐私说明。

升级使用现有兼容建表/补列流程。数据库和签名密钥必须保持原路径；建议升级前备份数据库，仍只运行一个 Uvicorn worker。不能用首页或后台可访问作为真实解析成功的证据。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET/PATCH /api/admin/users/{uid}/quota` | 获取、覆盖每日限额；`daily_limit: null` 恢复全局 |
| `GET/POST /api/admin/users/{uid}/credits` | 查询次数及流水，增加/设置可用通用额度 |
| `GET /api/quota` | 返回每日额度、通用额度与钱包信息，供首页分开展示 |

后台接口均要求管理员会话。每日设置使用版本冲突检查；通用额度调整同时使用版本检查及请求幂等键，重复提交同一操作不会重复增加额度。购买入账仅支持正向增加，不允许以购买名义覆盖余额。

## 验证记录

2026-09-27 的完整离线回归通过：451 项 Python 测试、120 项 Node 测试。覆盖混合额度预占与部分成功退款、管理员版本冲突和幂等入账、分享归因签名、账号/浏览器/网络去重、并发发奖与同作品最多 5 次限制。

本地原数据库备份后已升级至 v1.34.0，管理员登录、新增额度查询接口、数据库完整性及结构预检通过。未修改真实用户的额度，也未调用真实上游解析服务；这些结果不代表真实平台解析或在线支付已实测。
