# 解析补全与错误边界审查

版本：1.21.0；日期：2026-09-08。

## 已完成的修改

| 审查范围 | 原问题 | 修改结果 |
|---|---|---|
| 单条、批量、开放 API、分享 worker | 抖音在多处被强制分流到官方链路 | 统一优先请求主解析服务，失败时再使用官方补充链路 |
| 缺失字段 | 主响应无媒体时直接报错，缺作者和互动数时没有补齐 | 按需补媒体、作者、互动数、封面、时长和尺寸；只有官方元数据时也可补充已有主媒体 |
| 数据合并 | 作者补充接口用较粗略的粉丝数覆盖精确值，获赞类型不一致 | 仅补空值；保留有效统计 0；作者计数统一为整数或 null；不混合不同作品或两套媒体地址/下载端点 |
| 缓存与媒体任务 | 主结果缓存被绕过，抖音后台媒体任务被拒绝 | 主缓存正常复用；过期时按统一优先级刷新；后台成功缺媒体或失败时也可官方补充 |
| 播放与分享 | 主媒体过期后只能等待后台重新获取 | 受签名保护的同源端点可按保存的抖音来源补充；Range 416 不触发错误兜底；分享页无需阻塞 HTML 请求 |
| 页面与公开接口 | 管理页面、状态响应和错误显示底层名称、域名或原始响应 | 使用中性名称；不公开固定接口基址；新增中性媒体、文案和管理路由，并继续接受历史路由 |
| 历史错误 | 已保存的任务和管理测试错误可再次泄露上游信息 | 写入与读取均净化，保留稳定的状态码和可操作说明 |
| 中英文说明 | FAQ、隐私说明与 API 文档仍宣称抖音不会提交主服务 | 同步为主服务优先和官方补充，保留第三方处理的必要说明 |

内部数据库字段、函数名和服务端固定配置保留兼容，不迁移现有业务数据。普通解析依旧不请求语音转录；付费 API 的预扣、失败退款、媒体签名、域名白名单和代理策略沿用原有边界。

## 当前外部限制

现有主解析服务凭据实际返回 HTTP 401；系统成功使用官方补充链路完成解析。主服务成功、缺失字段及故障组合使用隔离的上游响应回归验证，不能将其描述为主服务实时成功。需要在管理后台更新有效服务凭据，才能恢复主服务的实时取数。

验收使用隔离服务，没有修改现有账户、额度或服务配置，也没有重启本机原有服务或部署线上。现有运行进程需重新加载代码才会使用新版本。
