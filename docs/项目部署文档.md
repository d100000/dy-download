# 项目部署、升级与验收文档

更新：2026-09-11 · 对应应用版本 **v1.31.0** · 完整版仓库：[d100000/dy-download](https://github.com/d100000/dy-download)

本文按当前根目录 `server.py` 和 `static/` 编写。`oss/` 是独立旧精简版，不用于本项目生产部署；不要运行会覆盖远程历史的 `oss/publish.sh`。

## 1. 发布判断与运行要求

发布完成需要四项证据：本地与 GitHub 提交一致、服务器代码一致、运行进程版本一致、公网功能验收通过。`git pull` 成功只说明磁盘更新，**不代表服务已重启**。首页底部和响应头展示前端版本，`/healthz` 展示进程应用版本；时间戳还受文件修改时间影响，跨主机应先比较应用版本及 Git 提交，再比较文件内容。

2026-09-10 已将 `https://dy.bobdong.cn` 从运行中的 **1.24.2** 更新至 **1.29.2**，公网及回环的后端/前端版本均已核对通过。实际部署位置与验收记录见第 10 节。后续发布仍需重新验收，不能沿用本次结论。

| 项目 | 当前要求 |
|---|---|
| Python | 推荐 3.12；回归兼容 3.9 / 3.12 |
| Python 依赖 | `requirements.txt` 引用 `requirements-lock.txt`；升级时重新安装，不能只拉代码 |
| 官方补全 | 只读取 HTTP 返回的 SSR / JSON-LD；不再安装或启动 Chrome/Chromium |
| Node.js | 22，用于单元测试；生产运行静态页面无需 Node 或前端构建 |
| 数据库 | SQLite WAL，应用自动建表补列；必须给整个数据目录写权限 |
| 应用进程 | **单 Uvicorn worker、单写实例**；管理员会话、验证码、限流和部分缓存仍在内存 |
| HTTPS / 反代 | 对外 Nginx + 有效证书，应用只监听回环；公网入口正确配置 `PUBLIC_ORIGIN` |
| 外部连通性 | 主解析服务 HTTPS；抖音网页/接口/CDN；使用 TikTok 时还需对应出口；微信接口按公众号要求使用服务器出口 |
| 磁盘与内存 | 不保存原视频，仅流式转发；仍需容纳SQLite/WAL、元数据、备份及可选代理内核 |

`API_JOB_WORKERS` 和 `ATC_WORKERS` 是应用内部任务线程数量，不能据此增加 Uvicorn workers。多实例架构尚未完成管理员会话、验证码与限流共享。

## 2. 数据与密钥：升级前必须确认

`DATA_DIR` 中至少包含：

- `app.db`：用户、会话、余额/账本、配额、API 任务、分享快照、运行配置。
- `app.db-wal` / `app.db-shm`：运行时可能存在，不能忽略 WAL 中尚未合并的数据。
- `config.json`：代理及策略。
- `.app-secret`：未显式设置密钥时自动生成，签名与摘要依赖它。
- `mihomo/`：使用订阅代理时的内核及配置。

**保留原 `DATA_DIR` 的绝对路径和签名密钥。** 换成空目录会导致用户、余额、分享看似丢失；换密钥会使旧媒体签名失效。已有部署若使用 `APP_SECRET` 或兼容 `CAPTCHA_SECRET`，必须保留原环境值，不可直接改成使用新生成文件。新安装可让应用生成 `.app-secret`，无需每次启动执行 `openssl rand`。

环境文件、数据目录和备份都不提交 Git。环境模板只含说明，真实管理员密码写到权限 `0600` 的 `/etc/douyin-dl.env`。不要用打印全部环境变量、`config.json` 或数据库配置表的方式诊断，以免暴露凭据。

普通用户使用 30 天 HttpOnly Cookie，服务端保存令牌摘要，重启后仍有效；退出/禁用立即失效。旧版内存登录状态首次升级后需要重新登录。管理员会话和算术题/滑块在重启后重新验证是预期行为。

## 3. 新安装：Docker

以下命令只适用于**首次新装**，已有站点按第 6 节升级，不要覆盖环境文件或数据。

```bash
git clone https://github.com/d100000/dy-download.git /srv/douyin-dl
cd /srv/douyin-dl
install -d -m 700 /srv/douyin-dl/data
install -m 600 deploy/app.env.example /etc/douyin-dl.env
# 编辑文件，填写强管理员密码和最终 HTTPS 域名。
sudoedit /etc/douyin-dl.env
docker build -t douyin-dl:1.31.0 .
docker run -d --name douyin-dl --restart unless-stopped \
  --env-file /etc/douyin-dl.env \
  -e DATA_DIR=/data \
  -p 127.0.0.1:3344:8000 \
  -v /srv/douyin-dl/data:/data \
  douyin-dl:1.31.0
curl -fsS http://127.0.0.1:3344/healthz
```

密码至少 12 位且不能使用默认值；未填写会拒绝启动。`/data` 必须挂载宿主机持久目录。镜像包含证书及锁定的运行依赖；不含测试文件、Node 或测试依赖。宿主机预检脚本的 `--data-dir` 使用宿主机路径，容器内 `DATA_DIR` 是 `/data`。

先完成 HTTPS 反代再测试注册登录；模板开启 Secure Cookie，在纯 HTTP 公网下不能正常持久登录。不要为临时测试关闭生产 Cookie 安全配置。

## 4. 新安装：systemd + Python

以下系统依赖安装命令为 Debian/Ubuntu 示例；OpenCloudOS 等系统使用相应包管理器安装 Python 与证书。不再需要浏览器。

```bash
apt-get update
apt-get install -y python3 python3-venv ca-certificates
git clone https://github.com/d100000/dy-download.git /srv/douyin-dl
cd /srv/douyin-dl
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
useradd --system --home-dir /srv/douyin-dl --shell /usr/sbin/nologin douyin
install -d -o douyin -g douyin -m 700 /srv/douyin-dl/data
install -m 600 deploy/app.env.example /etc/douyin-dl.env
sudoedit /etc/douyin-dl.env
install -m 644 deploy/douyin-dl.service /etc/systemd/system/douyin-dl.service
systemd-analyze verify /etc/systemd/system/douyin-dl.service
systemctl daemon-reload
systemctl enable --now douyin-dl
curl -fsS http://127.0.0.1:3344/healthz
```

若系统 Python 不是目标版本，显式使用 `python3.12 -m venv .venv`。服务账号必须能读取源代码/静态文件，数据目录仅服务账号读写。不要把位于 `/root/workspace/...` 的旧部署直接套入 `/srv/...` 模板；先确认原启动方式、端口、工作目录和数据位置，再迁移。裸进程、systemd 和 Docker 不可同时占用同一端口或数据目录。

v1.31.0 已移除服务端浏览器抓取，旧 DOUYIN_BROWSER_* 配置不再生效；无需卸载其他项目仍在使用的浏览器。

## 5. Nginx、HTTPS 和 CDN

模板：[deploy/nginx.conf.example](../deploy/nginx.conf.example)。替换域名、证书路径、反代端口后安装到 Nginx 的 `http {}` 配置范围：

```bash
nginx -t
systemctl reload nginx
```

证书需先按现有证书管理方案签发。模板包含 HTTP 跳转 HTTPS，关闭 access log，覆盖客户端传入的 X-Forwarded-For。若前面有 CDN，仅信任已核验的 CDN 地址段，由 Nginx 还原 `$remote_addr`；不要信任任意公网请求自带的真实 IP 头。

媒体匹配覆盖 `/api/media/video/`、`/api/douyin/video/`、`/api/video/`、旧兼容路由及 `/api/douyin/image/`。关闭媒体缓冲和代理缓存、透传 Range、设置 300 秒读取超时。Nginx 的缓冲行为参见 [官方 proxy 模块文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering)。

CDN 不缓存 `/api/*`、首页、分享页 HTML 或带签名媒体。静态图标只有匹配当前 `?v=` 时才使用长期缓存；前端时间戳由服务启动时读取文件修改时间生成。更新文件后重启并核对 `X-App-Version`、`X-Frontend-Version`、`Cache-Control`，不要仅刷新浏览器。

## 6. 现有部署升级流程

### 6.1 先盘点再更新

记录 Git 提交、运行版本、原启动方式、应用工作目录、监听端口、真实数据目录、外部环境文件位置。只读查询，不输出密码、API Key、Cookie 或完整签名链接。确认工作区无需要保留的业务改动；存在未提交文件时先核对，不能 `git reset --hard` 或 `git clean`。

```bash
cd /实际项目目录
git status --short
git rev-parse HEAD
curl -fsS http://127.0.0.1:实际端口/healthz
git fetch origin
git log --oneline HEAD..origin/main
```

### 6.2 备份与维护窗口

暂停入口写请求，等待已领取任务结束；停止应用后备份**整个原数据目录**及外部环境文件，同时记录原 Git 提交/镜像标识。保持备份私有权限，异地保存。使用旧版本代码回滚余额系统时，应评估数据库兼容性并保留升级后账本，不能直接覆盖已经发生交易的数据。

可用 Python SQLite backup API 做运行中一致性数据库副本，例如：

```bash
python3 - /实际数据目录/app.db /私有备份目录/app.db <<'PY'
import sqlite3, sys, os
from pathlib import Path
target = Path(sys.argv[2])
if target.exists():
    raise SystemExit('备份目标已存在，停止以免覆盖')
os.umask(0o077)
with sqlite3.connect(Path(sys.argv[1]).resolve().as_uri() + '?mode=ro', uri=True) as src:
    with sqlite3.connect(target) as dst:
        src.backup(dst)
        if dst.execute('PRAGMA quick_check').fetchone()[0] != 'ok':
            raise SystemExit('备份校验失败')
PY
```

该命令仅备份数据库，环境密钥、`.app-secret`、代理配置仍需另行备份。运行中不要仅 `cp app.db`；一致性备份方式参见 [Python SQLite backup 文档](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup)。要取得配置、密钥、数据库整体一致的回滚点，仍推荐维护窗口停服后备份全目录。

### 6.3 安装与重启

```bash
git merge --ff-only origin/main
# systemd / venv：先维护停服，再更新运行依赖。
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
systemctl restart douyin-dl
curl -fsS http://127.0.0.1:3344/healthz
```

Docker：先构建新版带版本标签的镜像；维护窗口执行 `docker stop --time 120 douyin-dl`，完成备份后移除旧容器，再使用第 3 节相同的环境文件、数据卷、端口重建，换成新镜像标签。保留上一版镜像以便回滚；不要删除数据卷。宿主机源码更新后仍需 `docker build` 和重建容器。

systemd 模板有变更时检查实际服务差异后安装，再 `systemctl daemon-reload`。不要以新模板覆盖已有环境密钥。`run.sh` 只在首次创建虚拟环境时安装依赖，因此已有 `.venv` 必须显式重新安装 requirements。

### 6.4 自动数据库升级

应用启动时按 `PRAGMA table_info` 补列并建立缺失表/索引，无需手工执行 ALTER。v1.24.2 升级到当前版重点检查：

| 数据结构 | 对应功能 |
|---|---|
| `user_sessions` | 登录状态跨重启保存 |
| `users.balance_cents/reserved_cents/spent_cents/wallet_version`、`wallet_ledger` | 网页余额编辑、收费、退款、并发控制 |
| `quota_reservations.user_id/free_units/price_cents` | 免费次数优先与价格快照 |
| `parse_snapshots.source_url/canonical_url`、`shares.source_url` | 持久保存原链接，媒体过期后可续期 |
| `shares.parse_status/assigned_origin` 及租约字段 | 异步分享、去重和重启恢复 |
| `atc_cache.work_url`、`atc_jobs` 租约/配额字段 | 媒体刷新来源、持久队列、转录结算 |
| `job_items`、`api_ledger` | 开放 API 预扣、逐条结算、失败退款 |

升级会尝试从旧媒体缓存补齐来源；**旧记录本来就没有原链接和完整元数据时，数据库迁移无法凭空恢复**，需管理员用原分享链接重新解析或执行针对性修复。不要制造标题或把缺失互动数写成 0。

### 6.5 回滚

停止接收写请求并保存故障现场的数据库/账本，停服；恢复上一版代码或镜像及对应依赖、原环境文件与原签名密钥。只有确认升级后没有新增交易，或已完成账本迁移/对账时，才可恢复升级前数据。若只回滚应用，需要先在备份副本验证旧代码对新数据库的兼容性。重启后再次核对版本、余额、分享与登录状态。

## 7. 后台配置与功能边界

| 配置位置 | 必须确认的内容 |
|---|---|
| `/admin_d` → 解析服务 | 服务已启用、Key/Secret 有效、权限/余额满足；“已配置”不等于鉴权通过 |
| 用户 → 网页额度与计费 | 登录普通用户每日免费解析次数 0–10000，默认 10；修改即时生效，不重置当天已用量 |
| 用户 → 余额编辑 | 以分记账；管理员可调整可用余额，写入独立账本；验证操作权限及重复提交保护 |
| 网页解析/文案价格 | 默认每次 3 分；免费次数先用，之后预扣余额，成功结算，失败释放；价格 0 表示免费 |
| API 单价与 Key | 开放 API 单独余额/账本，不与网页用户余额混用 |
| 文案提取 | 当前功能是音视频语音转文字；独立开关和免费次数。**图片 OCR 并未实现**，不能把转录配置称为 OCR |
| 代理池 | 默认代理优先，空池/全部失败后服务器直连；显式开启严格代理模式则必须有可用代理 |
| 分享设置 | 主分享域名、备用域名池、公众号配置；修改 AppID/Secret 会清空票据，未配置或失败时静默降级 |
| 功能检查 | 管理员启动真实检查，验证主服务、官方补全、浏览器及 1 字节媒体预检；不覆盖完整下载和微信真机 |

主服务优先提供下载地址。抖音元数据缺失时通过官方链路补全；TikTok 已接入统一解析、快照、分享与下载接口，但依赖主服务及可用网络，不具备抖音专用官方补全能力。

解析后存完整展示快照约 24 小时；分享快照默认匿名 7 天、登录 30 天。来源仅保存提取出的分享链接/作品链接，不保存整段分享文本。分享 GET 读取后台快照，不实时重新解析；浏览器打开后做媒体元数据预检，失效才请求有界续期任务，下载时重读后台签名，不重复扣解析次数、不延长分享有效期。

## 8. 服务器部署验收矩阵

用专用测试账号与测试作品验收，不修改真实用户余额/当天免费次数来制造测试条件。

| 功能 | 单元回归 | 服务器必须执行的检查与通过条件 |
|---|---|---|
| 版本、静态资源 | 页面响应头、无模板残留、缓存规则 | 本机和公网 `/healthz`、首页版本一致；文件提交一致；CDN 无旧 HTML |
| 依赖/浏览器/数据 | 新环境依赖检查、旧库迁移、预检脚本 | `pip check`；实际浏览器启动；数据权限、磁盘、SQLite quick_check；仅一个写实例 |
| 注册/登录 | 算术→滑块、非法答案、会话失效、重启持久化 | HTTPS 注册/登录，浏览器重开和服务重启仍登录；退出/禁用失效 |
| 免费次数、网页钱包 | 免费→付费、并发预扣、价格快照、失败退款 | 测试账号用尽免费次数后成功扣 3 分；失败不扣；后台调整次数/价格立即生效 |
| API Key 与批量任务 | 幂等、重复领取、并发扣款、持久任务 | 测试 Key 提交、轮询、部分失败退款及重启续跑；余额和账本一致 |
| 抖音解析/补全 | 上游字段兼容、缺失字段补全、零值、错误中性化 | 使用下方真实示例，检查标题、作者、点赞/评论/收藏/分享；分别确认主服务与官方补全状态 |
| TikTok | 平台识别、白名单、刷新、签名及失败分支 | 使用当前可访问公开作品实际解析和下载，确认服务器/代理出口可达 |
| 解析页下载 | 主链接优先、失效续期、同源兜底、状态码、并发 | 点击下载获取完整 MP4；200、媒体类型、文件长度一致、可以播放；验证 Range 206 |
| 分享页 | 快照、标题/互动数、旧签名刷新、失效/下架 | 已有分享打开保留标题/作者/互动数据；重启不丢；正常打开不重新解析；过期媒体续期后下载正常 |
| 图片/批量/导出 | 图片签名与限额、Excel 实际文件、防公式注入 | 图集显示和下载，批量导出能打开，完整计数未丢失 |
| 文案提取 | 独立配额、任务状态、收费退款 | 主服务转录权限有效，真实任务返回文案；不要把此项当图片 OCR 已部署 |
| 管理后台 | 鉴权、用户余额、配置、检查、投诉、流量 | 后台各模块能读取数据，编辑操作重启后保留；非管理员不可访问 |
| 代理/订阅 | 策略、失败回退、隔离与进程控制 | 可用代理出站；空池直连；严格模式报错；可选内核在本机私有端口运行 |
| 微信分享卡片/海报 | 签名、票据缓存、异常降级、二维码 | 公众号域名/IP 白名单；微信 Android/iOS 内打开、起播、右上角分享卡片与海报保存 |
| 多语言 | 首页/分享页动态状态与已有语言字典回归 | 中英切换，标题和作者不被翻译；移动端 loading、报错与余额提示完整 |

真实抖音示例：`4.64 :7pm M@J.VY 03/02 ZmD:/ 替你自由 https://v.douyin.com/qFnZK0HPwBo/ 复制此链接，打开Dou音搜索，直接观看视频！`

互动数随时间变化，不应写死预期值；只断言返回的是有效整数、0 正常显示、缺失项隐藏。标题缺失时分开看主服务响应和官方补全，不能仅看到视频可播就标记功能全通过。

### 只读预检命令

```bash
python3 tools/deploy_check.py --base-url http://127.0.0.1:3344 --data-dir /实际数据目录
```
