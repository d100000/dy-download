# 发布审查与测试报告

日期：2026-09-10 · 版本：**v1.29.2** · 审查基线：`6f0d522`（v1.29.1）

## 结论

已完成当前功能链路审查、补充回归和两套 Python 环境测试。**287 项 Python 测试、84 项 Node 前端测试均通过**，无跳过、无失败；本次增加 31 项 Python 测试。当前本地服务已启动 v1.29.2，原分享数据保留，完整视频下载再次验证通过。

**线上现已部署 v1.29.2。** 恢复服务器终端访问后，在隔离 Python 3.11 环境跑通同一套回归，备份并保留原数据/密钥，将旧进程迁入 systemd，核对公网版本、数据库迁移及真实解析/下载链路。微信真机、TikTok 真实作品及真实付费交易仍未执行，不将这些项目标记为实测通过。详见 [项目部署文档](项目部署文档.md) 第 10 节。

## 审查发现与修复

| 发现 | 影响 | 本次处理 |
|---|---|---|
| Docker 示例每次运行重新生成签名密钥 | 重建后旧下载签名失效，部署之间难以定位差异 | 改为持久环境文件与数据卷；明确新装自动保存密钥、升级必须保留原值 |
| Nginx 媒体规则未覆盖 `/api/media/video/` | 新下载线路未应用流式缓冲/超时策略 | 新模板覆盖主视频、官方视频、兼容路径、图片与续期端点，关闭缓存、透传 Range |
| 测试依赖未固定，运行依赖随安装时间变化 | 本地与服务器的 TestClient/Starlette 组合可能不同 | 锁定已验证依赖，新增 `requirements-dev.txt`，新 Python 3.12 环境从零安装并回归 |
| 测试发现可能重复导入共享环境夹具 | 同进程出现不同 server 模块引用或错误数据目录 | 测试目录包化，统一 `unittest discover -s tests -t .`，提供 `tools/test.sh` |
| 微信签名返回上游原始错误，网络/畸形响应可能触发 500 | 泄露内部信息，分享卡片异常影响接口 | 中性 `enabled:false` 降级，校验响应和票据有效期，不保存无效新票据 |
| 更改 AppID 未清空票据，并发请求重复刷新 | 旧票据与新 AppID 混用、额外请求上游 | AppID/Secret 变更均失效缓存；票据刷新与凭据编辑使用同一锁 |
| 缺少发布环境只读检查入口 | 拉取代码后难以确认进程、前端、数据库升级情况 | 新增 `tools/deploy_check.py`，缺库不创建、旧库不迁移，错误返回非零状态 |

同时补充真实 Excel/二维码产物、投诉处理、后台辅助接口权限、流量统计、SEO 资源、独立 CLI 视频/图集及部署预检自身的测试。GitHub Actions 使用与本地相同入口，覆盖 Python 3.9 / 3.12、Node 22；推送会触发 CI，不自动部署生产。
